# Change Note: 随机美图上游标签限制修复

## 1. What Changed

修复 `random_beauty` 调用 Random Mage 时返回 HTTP 400 的问题，并增加告警日志。

原因是插件本地维护了 52 个安全排除标签，而 Random Mage 新增了 `excluded_tags <= 50` 的参数校验。修复后：

- 上游请求最多发送 50 个排除标签。
- 本地仍保留完整 52 个标签进行二次复核。
- `school swimsuit` 和 `sex toy` 作为当前溢出的低增益短语被留在本地过滤，不再发送给上游。
- 首次发生标签截断时记录一次 Warn。
- 上游返回非 2xx 状态时记录状态码 Warn。

## 2. Why This Change Was Needed

旧代码把所有本地安全标签逐个加入 `excluded_tags`。上游接口原先接受这些参数，但新版本限制最多 50 个，因此每次请求都在候选选择前失败，重试两次后用户只能收到“图难产了”。

修复没有删除本地安全词。上游只负责减少候选，本地 `metadataSafe` 仍检查完整标签集合，因此不会因为适配上游参数限制而放宽本地安全策略。

## 3. Files Changed

- `internal/bizplugin/random_beauty/provider.go`：增加上游标签数量上限、低增益溢出项选择和 Warn 日志。
- `internal/bizplugin/random_beauty/plugin.go`：将 BusinessRegistry 注入的 zap Logger 传给 Provider。
- `internal/bizplugin/random_beauty/filter.go`：说明完整本地过滤词和上游 50 项参数上限的分工。
- `internal/bizplugin/random_beauty/provider_test.go`：验证请求只带 50 个标签、保留高风险词、记录一次截断 Warn。

## 4. Core Flow After The Change

```text
本地 52 个安全词
  -> providerExcludedTags()
  -> 上游最多 50 个词
  -> Random Mage 返回候选
  -> 本地 metadataSafe() 继续检查完整 52 个词
  -> 下载、视觉审核、发送
```

如果上游以后再次返回非 2xx，Provider 会记录状态码，Selector 仍按已有重试策略处理。

## 5. Key Code Concepts

### 上游契约适配

`maxProviderExcludedTags = 50` 把第三方 API 的参数限制封装在 Provider 内部，业务插件和本地安全词表不需要知道这个细节。

### 双层过滤

上游排除标签用于减少候选数量，本地过滤才是安全下限。即使某些低增益词因上游参数数量限制被省略，本地仍会拒绝命中的候选。

### Warn 日志

标签截断使用 `sync.Once`，同一个 Provider 实例只警告一次，避免每条正常请求都刷屏；非 2xx 响应则记录状态码，便于发现上游规则变化。

## 6. Important Implementation Details

- 只截断发送给 Random Mage 的标签，不修改 `mandatoryExcludedTags`。
- 当前溢出项为 `school swimsuit`、`sex toy`；对应的日文/中文敏感词仍保留。
- Provider 仍固定请求 `r18=0`、`r18_strict=1`、`ai_type=0`。
- Provider 不使用 `proxy` 或 `origin` 地址，仍只接受同源 `urls.local`。
- 日志只记录请求标签数量、上限、溢出数量和 HTTP 状态码，不记录图片内容或完整 URL。
- 本次修复没有新增服务、容器、数据库表或第三方依赖。
